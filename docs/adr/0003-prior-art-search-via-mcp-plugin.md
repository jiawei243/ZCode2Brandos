# ADR-0003: 现有技术检索以 MCP 插件接入，不进内核工具表

- 状态：已接受（2026-09-21）
- 关联：ADR-0001、专利产品规划 §5.1 #4、§9 风险 1

## 背景

专利撰写与 OA 答复依赖现有技术检索。数据源分层：公开源（Espacenet OPS、CNIPA 公开数据）先行，商业库（incoPat、智慧芽）API 后置采购。检索工具不应与 Agent 内核耦合。

## 决策

- 检索能力做成 **MCP server 插件**：定义统一的 search/parse 工具面，公开源与商业源实现同一接口，可替换。
- 分发走插件商店；连接与鉴权配置遵循 workspace 级 MCP 准入现状。
- 交底书内容属于商业秘密：检索 MCP 的外发请求必须经过 PreToolUse 保密拦截 hook（ADR-0001 质量门）审查目标地址，fail-closed。

## 理由（决策树 1–3 可行）

1. MCP 是 L0 已有能力，接新数据源零内核改动。
2. 统一 MCP 工具面 = 包装层，商业源替换不影响套件其余部分。
3. 内核工具表改动会直接造成上游分叉，无必要。

## 后果

- 数据源可用性是 P0 硬依赖：Espacenet OPS 需注册 key，CNIPA 公开数据覆盖/频率需 spike 验证；商业库是成本项。
- 保密拦截依赖 hook 对 MCP 工具参数的可见性，需在 P0 验收场景中实测（不出内网是验收条件之一）。
